# threadscombine — дорожная карта

Личный ИИ-помощник для Threads в виде расширения Chrome — свой аналог ThreadsAI.
Только для владельца: собственный ключ OpenRouter, данные в браузере, без сервера, входа и тарифов.
Владелец ведёт несколько тематических аккаунтов; цели — охваты, переходы и клиенты — равнозначны.

## Общие правила для всех частей

- **Никакой автопубликации.** ИИ готовит черновик и вставляет его в поле ответа; публикует человек
  одним нажатием. Нет имитации «живого человека» для обхода антиспама Threads, нет массовых
  действий без подтверждения. Публикация через официальные API сторонних сервисов (Postmypost) —
  только по явному действию владельца.
- **Свой код и свои промпты.** Код и промпты ThreadsAI не копируются; оригинал — только ориентир
  по возможностям.
- **ИИ только через ключ владельца** напрямую в OpenRouter, без посредников; расходы учитываются,
  лимиты на день и месяц останавливают вызовы.
- **Данные локально** (IndexedDB + `chrome.storage.local`), перенос — через файл экспорта.
- **Данные аккаунта — с `accountId`.** Всё, что относится к конкретному аккаунту, хранится отдельно
  и читается с фильтром по активному аккаунту.
- Каждая часть проходит свой цикл: спецификация → план → реализация субагентами с ревью.

## Части

| # | Часть | Что даёт | Зависит от |
|---|-------|----------|-----------|
| 1 | **Ядро** | Каркас MV3 (WXT + TypeScript + Preact), боковая панель, распознавание страницы Threads, клиент OpenRouter с запасными моделями и JSON-ответами, несколько аккаунтов, учёт расходов и лимиты, настройки, база Dexie, экспорт/импорт, журнал | — |
| 2 | **Парсер и аналитика** | Сбор постов из ленты, профиля, поиска; определение аккаунта, под которым выполнен вход; таблица с фильтрами по метрикам и периоду; деление на «зашедшие» и «не зашедшие» (HOT/COLD); аудит профиля относительно обычного уровня автора; **дневник публикаций** — свои посты и комментарии пересобираются через 1/24/72 ч, что зашло — подсказка генераторам; **список конкурентов** с сигналом «пост взлетает»; экспорт | 1 |
| 3 | **Контент** | **Паспорт стиля аккаунта** (описание, голос, можно/нельзя, лучшие примеры) — основа всех генераторов; разбор вирусности поста (несколько режимов); генерация веток по образцу и в своём стиле; крючки и идеи из ленты; **копилка** (кнопка «в копилку» под постом, теги, образцы для генерации); **защита от самоповторов**; история генераций; кнопки под постами в ленте | 1, 2 |
| 4 | **Комментарии** | ИИ-черновик ответа в выбранном стиле прямо в поле ответа; очередь черновиков по отобранным постам; **«входящие»** — ответы под своими постами с черновиками; фильтры постов и релевантности; защита от повторов (тот же пост/автор, одинаковые фразы) | 1, 2, 3 |
| 5 | **Программы и поиск клиентов** | Сценарии из шагов (сбор → фильтр → ИИ-отбор → черновики) с повторами; поиск клиентов: ИИ-запросы по описанию продукта → поиск в Threads → отбор людей с болью/запросом → доказательство и идея контакта → черновики ответов | 1–4 |
| 6 | **Чат-агент** | Чат, где ИИ сам вызывает инструменты частей 2–5: найти, разобрать, сгенерировать, запустить программу; библиотека продуктов и стилей | 1–5 |
| 7 | **Интеграции** | Отправка готовой ветки в Postmypost черновиком или отложенным постом (если тариф поддерживает Threads); уведомления в Telegram-бота владельца («найден клиент», «пост конкурента взлетает»); связка с пайплайном Reels: зашедшие темы Threads → идеи роликов, подписи Reels → ветки Threads | 1–5 |

Части 2–7 получают свои спецификации, когда до них доходит очередь; их состав выше — ориентир,
а не обязательство.

**Первое, что проверить в части 2:** надёжно ли читаются метрики своих постов и особенно своих
комментариев с веб-версии Threads — на этом стоит дневник публикаций.

## Парковка

Идеи, которые пока не берём: картинки и карусели через ИИ, мобильный доступ через Telegram-бота,
английский рынок, A/B-тест двух хуков.
