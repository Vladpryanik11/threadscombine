# Часть 1 «Ядро» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Каркас расширения Chrome «threadscombine»: боковая панель с вкладками, распознавание страницы Threads, клиент OpenRouter с запасными моделями и JSON-ответами, настройки, база, экспорт/импорт, журнал.

**Architecture:** WXT собирает MV3-расширение из трёх точек входа: боковая панель (Preact, «мозг»: UI, вызовы ИИ, база), контент-скрипт на Threads («глаза и руки», только по командам панели) и минимальный фоновый воркер (открывает панель). Общий код — в `src/` по модулям `ai`, `storage`, `messaging`, `threads`, `prompts`, `ui`; разделы интерфейса — в `src/features/*`, которые не импортируют друг друга.

**Tech Stack:** WXT 0.21, TypeScript (strict), Preact + @preact/signals, Dexie 4, zod 4, Vitest 5 + happy-dom + fake-indexeddb + @testing-library/preact, npm, Node 24.

**Spec:** [`docs/superpowers/specs/2026-10-04-core-design.md`](../specs/2026-10-04-core-design.md) — исполнители читают его вместе с планом; номера разделов ниже ссылаются на него.

## Global Constraints

- Node 24, npm. TypeScript `strict: true`. Код и идентификаторы — на английском, весь текст интерфейса — на русском, точные строки — из спеки.
- `permissions`: `storage`, `unlimitedStorage`, `sidePanel`. `host_permissions`: `https://*.threads.com/*`, `https://*.threads.net/*`, `https://openrouter.ai/*`. Других разрешений не добавлять.
- Ключ OpenRouter отправляется только на `https://openrouter.ai/api/v1/*`; в журнал, консоль и тексты ошибок не попадает.
- Модуль из `src/features/*` импортирует только `src/{ai,storage,messaging,threads,prompts,ui}`, никогда — другой `src/features/*`.
- API расширения — через `browser` из `wxt/browser`; в тестах это `fakeBrowser` (подключается плагином `WxtVitest`). Если `fakeBrowser` не реализует нужный метод — подменить его через `vi.spyOn`/присваивание в самом тесте.
- Обработчики `runtime.onMessage` отвечают через `sendResponse` и `return true` (Chrome ненадёжно поддерживает возврат промиса из слушателя).
- Никакого автоматического нажатия «Опубликовать» и имитации действий пользователя на Threads (правило дорожной карты).
- Код и промпты ThreadsAI не копировать.
- После каждой задачи проходят: `npm run typecheck`, `npm test`, `npm run build`.

## Review Focus

1. **Ключ вставлен с пробелами или переводом строки** (копирование со страницы OpenRouter) → сохраняется без пробельных символов. Тест — задача 5.
2. **Адреса Threads «с хвостами»**: завершающий `/`, `?xmt=…`, `#…`, `www.` и без, `threads.net`, имя с точкой и подчёркиванием (`/@john.doe_1`) → тип страницы определяется верно. Тест — задача 2.
3. **Сохранённой модели больше нет в каталоге OpenRouter** → выбор показывает её id с пометкой «(нет в каталоге)», экран не падает, вызовы идут на этот id. Тест — задача 11.
4. **Импорт чужого или битого файла** (не JSON, бэкап ThreadsAI, произвольный JSON) → «Это не файл резервной копии threadscombine», база не изменена. Тест — задача 6.
5. **Активная вкладка — `chrome://`, новая вкладка или страница без адреса** → «Откройте Threads», без исключений. Тест — задача 10.

**Interfaces:**
- Consumes: `PageContext`, `parsePageUrl`, `watchUrl` (задача 2).
- Produces:
  - `interface TabRequests { 'page:get': { req: void; res: PageContext }; ping: { req: void; res: { version: string } } }`
  - `interface Broadcasts { 'page:changed': PageContext }`
  - `class MessagingError extends Error { code: 'no_content_script' | 'unknown' }`
  - `sendToTab<K extends keyof TabRequests>(tabId: number, type: K, payload?: TabRequests[K]['req']): Promise<TabRequests[K]['res']>`
  - `onTabRequest<K extends keyof TabRequests>(type: K, handler: (payload: TabRequests[K]['req']) => TabRequests[K]['res'] | Promise<TabRequests[K]['res']>): () => void`
  - `broadcast<K extends keyof Broadcasts>(type: K, payload: Broadcasts[K]): Promise<void>` — ошибку «нет получателя» (панель закрыта) глотает
  - `onBroadcast<K extends keyof Broadcasts>(type: K, handler: (payload: Broadcasts[K], sender: { tabId?: number }) => void): () => void`
  - `startContentScript(deps?: { getHref?: () => string; target?: EventTarget }): () => void`

Ошибки Chrome с текстом «Receiving end does not exist» или «Could not establish connection» → `MessagingError('no_content_script')`.

### Task 5: Настройки

**Interfaces:**
- Consumes: `log` (задача 4).
- Produces:
  - `interface Settings` — ровно поля и значения по умолчанию из раздела 7 спеки (`version: 1`, `openRouterKey: ''`, `model: ''`, `fallbackEnabled: true`, `fallbackModels: []`, `reasoning: 'off'`, `requestTimeoutSec: 90`, `theme: 'auto'`)
  - `const DEFAULT_SETTINGS: Settings`, `const SETTINGS_KEY = 'settings'`
  - `migrateSettings(raw: Record<string, unknown>): Record<string, unknown>` — нет `version` (условная версия 0) → `version: 1`, известные поля сохраняются
  - `normalizeSettings(raw: unknown): { settings: Settings; repaired: string[] }` — чинит поле за полем: неверное → значение по умолчанию + имя в `repaired`; ключ без пробельных символов; `fallbackModels` — без повторов, без основной модели, не больше 2
