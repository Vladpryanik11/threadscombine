# Часть 1 «Ядро» — дизайн

Дата: 2026-10-04 · Статус: на проверке у владельца · Дорожная карта: [`docs/roadmap.md`](../../roadmap.md)

## 1. Цель

Рабочий каркас расширения Chrome, на который встанут части 2–7:

- боковая панель с навигацией по разделам и темой оформления;
- распознавание текущей страницы Threads;
- клиент OpenRouter (потоковый текст и ответы по JSON-схеме, запасные модели, понятные ошибки);
- несколько аккаунтов Threads: у каждого свои данные, переключатель в шапке;
- учёт расходов OpenRouter с необязательными лимитами на день и месяц;
- настройки, локальная база, экспорт/импорт, журнал событий.

Ядро само по себе не парсит, не генерирует контент и не пишет комментарии — это части 2–7.

### Критерии приёмки (ручная проверка в Chrome)

1. `npm run build` → «Загрузить распакованное» из `.output/chrome-mv3` → расширение ставится без ошибок.
2. На открытом Threads клик по иконке открывает боковую панель.
3. Панель показывает тип страницы: «Лента», «Профиль @user», «Пост», «Поиск „запрос“» или
   «Откройте Threads»; при переходах внутри Threads (без перезагрузки) плашка обновляется
   в течение 1 секунды; при переключении вкладки браузера — тоже.
4. В настройках: ввести ключ OpenRouter, выбрать основную и запасные модели, нажать «Проверить» —
   приходит ответ модели со временем, токенами и стоимостью. С неверным ключом — сообщение
   «Неверный ключ OpenRouter».
5. Вкладки Аналитика · Контент · Комментарии · Клиенты · Чат открываются и показывают заглушку «Скоро».
6. Экспорт создаёт JSON-файл; импорт этого файла в режиме «заменить» восстанавливает настройки
   (кроме ключа, если галочка не стояла) и данные, включая аккаунты.
7. При первом запуске есть аккаунт «Основной». Можно создать второй аккаунт из переключателя в шапке,
   переключиться на него (выбор сохраняется после закрытия панели), привязать @username, удалить
   с подтверждением; удалить последний аккаунт нельзя.
8. После «Проверить» в разделе «Расходы» растёт сумма «Сегодня»; лимиты на день и месяц сохраняются.

Автоматически после каждой задачи: `npm run typecheck`, `npm test`, `npm run build` — без ошибок.

### Вне рамок ядра

Парсинг, генерация, комментарии, программы, чат, интеграции — части 2–7. Автоматическое определение,
под каким аккаунтом выполнен вход в Threads, — часть 2 (в ядре аккаунт выбирается вручную).
Сервер, вход, тарифы, синхронизация между устройствами — не делаем вовсе (инструмент личный).

## 2. Технологии

- **WXT** (сборка MV3, дев-режим с перезагрузкой) + **TypeScript** (strict).
- **Preact** + `@preact/signals` для интерфейса; подключается через `@preact/preset-vite`
  в `wxt.config.ts`.
- **Dexie** — IndexedDB.
- **zod** (v4) — проверка настроек, файлов импорта и JSON-ответов ИИ; `z.toJSONSchema` — схема для
  structured outputs.
- **Vitest** + `fake-indexeddb` + `@testing-library/preact` — тесты.
- Пакетный менеджер — **npm**. Node 24.

Манифест:

- `permissions`: `storage`, `unlimitedStorage`, `sidePanel`.
- `host_permissions`: `https://*.threads.com/*`, `https://*.threads.net/*`, `https://openrouter.ai/*`.
- Разрешение `tabs` не нужно: адрес вкладок Threads виден благодаря `host_permissions`, у остальных
  вкладок адрес не виден — они считаются «не Threads».

## 3. Архитектура

Три исполняемые части с жёстко разделёнными ролями.

| Часть | Роль | Что в ней НЕ живёт |
|-------|------|--------------------|
| Боковая панель (`entrypoints/sidepanel/`) | «Мозг»: интерфейс, запуск задач, вызовы OpenRouter, работа с базой | Прямой доступ к DOM Threads |
| Контент-скрипт (`entrypoints/threads.content.ts`) | «Глаза и руки»: определяет страницу, позже читает данные и вставляет текст. Выполняет команды панели, решений не принимает | Вызовы ИИ, база, настройки |
| Фоновый воркер (`entrypoints/background.ts`) | Открывает панель по клику на иконку (`sidePanel.setPanelBehavior({ openPanelOnActionClick: true })`) | Любая бизнес-логика |

**Почему задачи живут в панели:** фоновый воркер MV3 засыпает примерно через 30 секунд простоя;
панель живёт, пока открыта. Следствие (осознанное ограничение): длинные задачи будущих частей
идут, пока панель открыта.

### Структура

```
threadscombine/
  wxt.config.ts
  entrypoints/
    background.ts
    sidepanel/            index.html, main.tsx, App.tsx
    threads.content.ts
  src/
    ai/                   клиент OpenRouter, каталог моделей, ошибки, JSON-режим
    storage/              settings.ts (chrome.storage), db.ts (Dexie), accounts.ts, spend.ts, backup.ts, journal.ts
    messaging/            contract.ts (типы сообщений), bus.ts (обёртка над chrome.runtime/tabs)
    threads/              page.ts (адрес → тип страницы), active-tab.ts (слежение за активной вкладкой)
    prompts/              промпты, по файлу на задачу, с id версии (в ядре — только промпт проверки ключа)
    ui/                   общие компоненты (Button, Field, Select, Toast…), тема
    features/
      settings/           экран настроек (ядро)
      placeholders/       заглушки разделов (ядро)
  tests/
```

**Правило границ:** модуль из `features/*` импортирует только `src/ai`, `src/storage`,
`src/messaging`, `src/threads`, `src/prompts`, `src/ui` и никогда — другой модуль `features/*`.

## 4. Сообщения панель ↔ вкладка (`src/messaging`)

Контракт — один файл `contract.ts`: карта «тип сообщения → данные запроса → данные ответа».
`bus.ts` — тонкая типизированная обёртка (~50 строк, без внешних библиотек):

- `sendToTab(tabId, type, payload) → Promise<Response>` — панель → контент-скрипт;
- `onMessage(type, handler)` — регистрация обработчика в контент-скрипте;
- `broadcast(type, payload)` / `onBroadcast(type, handler)` — контент-скрипт → панель
  (`chrome.runtime.sendMessage`; панель получает `sender.tab.id`).

Сообщения ядра:

| Тип | Направление | Запрос | Ответ |
|-----|-------------|--------|-------|
| `page:get` | панель → вкладка | — | `PageContext` |
| `page:changed` | вкладка → панель | `PageContext` | — |
| `ping` | панель → вкладка | — | `{ version: string }` |

```ts
type PageKind = 'feed' | 'profile' | 'post' | 'search' | 'other';
interface PageContext {
  kind: PageKind;
  url: string;
  username?: string; // для profile и post, без «@»
  postId?: string;   // для post
  query?: string;    // для search
}
```

Если `sendToTab` падает с «Receiving end does not exist» — во вкладке нет скрипта (открыта до установки);
обёртка возвращает типизированную ошибку `no_content_script`.

## 5. Распознавание страницы (`src/threads`)

`page.ts` — чистая функция `parsePageUrl(url): PageContext`:

| Адрес (хост `threads.com` или `threads.net`, с `www.` и без) | Тип |
|---|---|
| `/`, `/for_you`, `/following` | `feed` |
| `/@{user}` (и подпути `/replies`, `/reposts`, `/media`) | `profile` |
| `/@{user}/post/{id}` (и подпути, например `/media`) | `post` |
| `/search` с параметром `q` | `search` (без `q` — `other`) |
| всё остальное на Threads | `other` |

Контент-скрипт отслеживает смену адреса в одностраничном приложении: проверяет `location.href`
по событию `popstate` и по таймеру раз в 500 мс; при изменении отправляет `page:changed`.

`active-tab.ts` (в панели): держит сигнал `activeThreadsTab` — `{ tabId, page } | { status }`, где
`status` ∈ `not_threads` (активная вкладка не Threads), `needs_reload` (Threads, но скрипт не отвечает),
`loading`. Обновляется по `chrome.tabs.onActivated`, `chrome.tabs.onUpdated` (смена адреса, загрузка)
и `page:changed` от активной вкладки (сообщения от неактивных вкладок игнорируются).

## 6. Клиент ИИ (`src/ai`)

Ключ отправляется только на `https://openrouter.ai/api/v1/*`.

### Интерфейс

```ts
interface ChatMessage { role: 'system' | 'user' | 'assistant'; content: string }

interface AiRequest {
  purpose: string;          // для журнала: 'key-check', 'virality', …
  messages: ChatMessage[];
  temperature?: number;
  maxTokens?: number;
  signal?: AbortSignal;     // отмена пользователем
}

interface Usage { promptTokens: number; completionTokens: number; costUsd?: number }

type AiResult<T> =
  | { ok: true; value: T; model: string; usage?: Usage; switchedFrom: string[]; elapsedMs: number }
  | { ok: false; error: AiError };

interface AiError {
  code: 'no_key' | 'no_model' | 'budget_exceeded' | 'bad_key' | 'no_credits' | 'rate_limited'
      | 'model_unavailable' | 'timeout' | 'network' | 'bad_output' | 'cancelled' | 'unknown';
  message: string;          // по-русски, готово для показа
  status?: number;
  model?: string;
}

streamText(req: AiRequest, onDelta: (chunk: string) => void): Promise<AiResult<string>>;
generateJson<T>(req: AiRequest, schema: z.ZodType<T>, schemaName: string): Promise<AiResult<T>>;
listModels(opts?: { force?: boolean }): Promise<ModelInfo[]>;
```

Модель, рассуждение, таймаут, запасные модели и лимиты расходов клиент берёт из настроек, активный
аккаунт — из `accounts.ts`; вызывающий код их не передаёт.

### Лимиты и учёт расходов

- Перед запросом (кроме `purpose: 'key-check'`) клиент проверяет лимиты (раздел 7, «Расходы»):
  превышен — запрос не отправляется, ошибка `budget_exceeded`, без переключения моделей.
- Каждый полученный ответ модели, в котором есть `usage`, записывается в расходы — включая неудачные
  по формату ответы и повторный запрос «исправь формат»: деньги за них тоже списаны. Запись несёт
  активный аккаунт на момент запроса.
- Стоимость — `usage.cost` от OpenRouter; если её нет — по ценам каталога:
  `(promptTokens × promptPricePerM + completionTokens × completionPricePerM) / 1 000 000`;
  модели нет в каталоге — 0.

### Запросы

- `POST /api/v1/chat/completions`, заголовки `Authorization: Bearer <ключ>`,
  `X-Title: threadscombine`; в теле `usage: { include: true }`.
- `streamText`: `stream: true`, разбор SSE (`data: …`, игнор комментариев `: OPENROUTER PROCESSING`,
  конец по `[DONE]`); дельты отдаются в `onDelta`. Если поток оборвался после первых дельт —
  ошибка `network`, без переключения модели (частичный текст уже показан пользователю).
- `generateJson`:
  - модель поддерживает `structured_outputs` (по каталогу) → `response_format: { type: 'json_schema',
    json_schema: { name: schemaName, strict: true, schema: z.toJSONSchema(schema) } }`;
  - иначе — в конец системного сообщения добавляется JSON-схема и требование «ответь только JSON».
  - Из ответа снимаются обёртки ```` ```json ````, текст парсится и проверяется схемой.
  - Не прошло → один повторный запрос к той же модели: исходные сообщения + ответ модели + «исправь
    формат: <ошибки проверки>». Не прошло снова → `bad_output`.
- Рассуждение: если уровень не `off` и модель поддерживает `reasoning` → `reasoning: { effort }`;
  иначе параметр не передаётся.
- Таймаут — из настроек (по умолчанию 90 с), через `AbortController`; отмена пользователем → `cancelled`.

### Запасные модели

Цепочка: основная модель → до двух запасных (если включено). Переход к следующей модели — только
до получения первого токена ответа:

| Ситуация | Код | Переключать? |
|----------|-----|-------------|
| Ключ не задан | `no_key` | нет (запрос не отправляется) |
| Основная модель не выбрана | `no_model` | нет (запрос не отправляется) |
| Превышен лимит расходов | `budget_exceeded` | нет (запрос не отправляется) |
| HTTP 401 / 403 | `bad_key` | нет |
| HTTP 402 | `no_credits` | нет |
| HTTP 429 | `rate_limited` | да |
| HTTP 404 / 400 с «model» в тексте ошибки, 5xx | `model_unavailable` | да |
| Таймаут | `timeout` | да |
| Пустой ответ (нет текста) | `model_unavailable` | да |
| Сетевая ошибка до ответа | `network` | да |
| `bad_output` после повтора | `bad_output` | да |
| Отмена пользователем | `cancelled` | нет |

Если все модели цепочки упали — возвращается ошибка последней. Успешный результат несёт
`switchedFrom` (список моделей, на которых не получилось) — интерфейс показывает «Переключились на X».

### Сообщения об ошибках

| Код | Текст |
|-----|-------|
| `no_key` | «Укажите ключ OpenRouter в настройках» |
| `no_model` | «Выберите модель в настройках» |
| `budget_exceeded` | «Достигнут дневной лимит расходов ($X). Измените лимит в настройках» или «Достигнут месячный лимит расходов ($X). Измените лимит в настройках»; X — лимит с двумя знаками после точки, например `$5.00` |
| `bad_key` | «Неверный ключ OpenRouter» |
| `no_credits` | «На балансе OpenRouter закончились деньги» |
| `rate_limited` | «OpenRouter ограничил частоту запросов, попробуйте через минуту» |
| `model_unavailable` | «Модель {id} сейчас недоступна» |
| `timeout` | «Модель не ответила за {N} с» |
| `network` | «Нет связи с OpenRouter» |
| `bad_output` | «Модель вернула ответ в неверном формате» |
| `cancelled` | «Остановлено» |
| `unknown` | «Ошибка OpenRouter: {текст ответа, до 200 символов}» |

### Каталог моделей

`GET /api/v1/models` → `ModelInfo[]`:

```ts
interface ModelInfo {
  id: string; name: string;
  promptPricePerM: number; completionPricePerM: number;   // $ за 1M токенов
  contextLength: number;
  supportsStructuredOutputs: boolean;  // 'structured_outputs' в supported_parameters
  supportsReasoning: boolean;          // 'reasoning' в supported_parameters
}
```

Берутся только модели с текстовым выходом. Кэш в `chrome.storage.local` на 24 часа; кнопка
«Обновить список» — `force`. Без сети и с пустым кэшем выбор модели показывает ошибку и кнопку повтора.

Рекомендуемые модели — короткий список id в `src/ai/recommended.ts` (стартовый:
`deepseek/deepseek-v4.1-flash`, `openai/gpt-6-luna`, `qwen/qwen3.8-flash`). В выборе они идут первыми
с пометкой «рекомендуем», но только если есть в живом каталоге.

## 7. Хранение (`src/storage`)

### Настройки — `chrome.storage.local`, ключ `settings`

```ts
interface Settings {
  version: 1;
  openRouterKey: string;                     // '' по умолчанию
  model: string;                             // '' — модель не выбрана
  fallbackEnabled: boolean;                  // true
  fallbackModels: string[];                  // до 2, без повторов и без основной
  reasoning: 'off' | 'low' | 'medium' | 'high';  // 'off'
  requestTimeoutSec: number;                 // 90, допустимо 15–300
  theme: 'auto' | 'light' | 'dark';          // 'auto'
  activeAccountId: string;                   // '' — первый аккаунт
  dailyBudgetUsd: number | null;             // null — без лимита; иначе 0.01–1000
  monthlyBudgetUsd: number | null;           // null — без лимита; иначе 0.01–1000
}
```

Ключ, модели, тема и лимиты — общие для всех аккаунтов.

- `getSettings()` читает, проверяет схемой, недостающие поля заполняет значениями по умолчанию,
  неверные значения заменяет значениями по умолчанию (с записью в журнал).
- `updateSettings(patch)` проверяет и сохраняет; сигнал `settings` в панели обновляется
  по `chrome.storage.onChanged`.
- Миграции: функция на каждый переход версии; в ядре версия одна, механизм — с тестом
  на условную версию 0 → 1.
- Пока модель не выбрана, любой вызов ИИ возвращает `no_model`.

### База — Dexie, имя `threadscombine`

Версия 1 (ядро):

| Таблица | Индексы | Что хранит |
|---------|---------|------------|
| `journal` | `++id, ts, level, area` | журнал событий |
| `accounts` | `id, createdAt` | аккаунты Threads |
| `spend` | `++id, ts, accountId, purpose` | расходы на ИИ |

Каждая следующая часть добавляет таблицы новой версией схемы (`db.version(n).stores({...})`),
не изменяя чужие таблицы.

**Правило аккаунтов для частей 2–7:** всё, что относится к конкретному аккаунту (посты, стиль,
продукты, черновики, копилка…), хранится в таблицах с индексом `accountId`, и чтение идёт с фильтром
по активному аккаунту.

### Аккаунты (`accounts.ts`)

```ts
interface Account {
  id: string;              // crypto.randomUUID()
  name: string;            // 1–40 символов после обрезки пробелов
  threadsUsername: string; // '' или [a-z0-9._]{1,30}: без «@», в нижнем регистре; уникален среди аккаунтов
  color: string;           // из палитры из 8 цветов, по кругу
  createdAt: number;
}
```

- При первом обращении, если аккаунтов нет, создаётся «Основной».
- Активный аккаунт — `settings.activeAccountId`; пустой или ссылается на несуществующий — активным
  становится самый ранний аккаунт (и это сохраняется).
- Удаление: последний аккаунт удалить нельзя («Нельзя удалить последний аккаунт»). Удаляются строки
  этого аккаунта во всех таблицах с индексом `accountId`, **кроме `spend`** — учёт денег не обнуляется.
  Удалили активный — активным становится самый ранний из оставшихся.

### Расходы (`spend.ts`)

```ts
interface SpendRecord {
  id?: number; ts: number; accountId: string; purpose: string; model: string;
  promptTokens: number; completionTokens: number; costUsd: number;
}
```

- «Сегодня» — текущие локальные сутки, «за месяц» — текущий календарный месяц, по всем аккаунтам.
- Лимиты из настроек сравниваются с этими суммами: сумма ≥ лимита → лимит достигнут
  (сначала проверяется дневной, потом месячный).
- Сводка для экрана: сегодня, за месяц, за месяц по задачам и по аккаунтам (удалённый аккаунт
  показывается как «Удалённый аккаунт»).

### Журнал (`journal.ts`)

`log(level: 'info' | 'warn' | 'error', area: string, message: string, details?: unknown)` —
запись в `journal`; хранится не больше 500 последних записей (лишние удаляются при записи).
В журнал пишутся: ошибки и переключения моделей ИИ, отказы проверки настроек, ошибки сообщений
с вкладкой. Ключ OpenRouter и полные тексты промптов в журнал не пишутся.

### Экспорт / импорт (`backup.ts`)

Формат файла `threadscombine-backup-YYYY-MM-DD.json`:

```json
{ "format": "threadscombine-backup", "formatVersion": 1, "exportedAt": "ISO-дата",
  "dbVersion": 1, "settings": { "…": "без openRouterKey, если не отмечено" },
  "tables": { "journal": [ ], "accounts": [ ], "spend": [ ] } }
```

- Экспорт обходит все таблицы базы (`db.tables`), поэтому новые таблицы будущих частей попадают
  в файл без доработки. Скачивание — через `Blob` + ссылку `download` из панели.
- Импорт проверяет файл схемой; файл с `dbVersion` новее текущей базы отклоняется
  («Файл из более новой версии расширения»).
  - «Заменить»: очистить все таблицы, загрузить данные из файла, заменить настройки
    (ключ — только если он есть в файле, иначе текущий сохраняется).
  - «Объединить»: `bulkPut` по первичным ключам, настройки не трогаются.
  - Всё в одной транзакции Dexie: при ошибке база остаётся как была.
  - После импорта действуют правила аккаунтов: нет ни одного — создаётся «Основной»; активный
    не найден — активным становится самый ранний.
- «Очистить всё» — удаляет данные базы (включая аккаунты и расходы) и сбрасывает настройки
  (ключ сохраняется), с подтверждением; после этого снова есть только «Основной».

## 8. Интерфейс панели

- **Верхняя полоса:** переключатель аккаунта (цветная точка + имя; в списке — все аккаунты
  и «+ Новый аккаунт» с полем имени), плашка страницы (из `activeThreadsTab`: «Лента», «Профиль @user»,
  «Пост @user», «Поиск „q“», «Threads», «Откройте Threads», «Обновите вкладку» + кнопка перезагрузки
  вкладки) и плашка модели (имя основной модели; «Модель не выбрана» — ведёт в настройки).
- **Вкладки:** Аналитика · Контент · Комментарии · Клиенты · Чат · Настройки. В ядре первые пять —
  заглушка «Скоро» с одной строкой о будущем содержимом раздела. Выбранная вкладка запоминается.
- **Тема:** CSS-переменные на `:root`, атрибут `data-theme` (`auto` следует `prefers-color-scheme`).
- **Уведомления (toast)** для результатов и ошибок; ошибки ИИ показывают `AiError.message`.

### Экран «Настройки»

1. **Ключ OpenRouter** — поле-пароль с кнопкой «показать», ссылка «Где взять ключ»
   (`https://openrouter.ai/keys`), кнопка **«Проверить»**: запрос `purpose: 'key-check'` с коротким
   промптом («Ответь одним словом: работает») через `streamText`; показывает ответ, модель, время,
   токены и стоимость или ошибку.
2. **Модели** — основная (выпадающий список с поиском по id/имени, ценой «$вход / $выход за 1M»,
   рекомендуемые сверху), переключатель «Запасные модели», до двух запасных, «Рассуждение»
   (недоступно, если основная модель его не поддерживает), «Таймаут, сек». Кнопка «Обновить список».
3. **Оформление** — авто / светлая / тёмная.
4. **Аккаунты** — список: имя (редактируется), @username в Threads, «Удалить» с подтверждением
   «Удалить аккаунт и все его данные?» (у последнего аккаунта кнопка недоступна).
5. **Расходы** — «Сегодня: $X · За месяц: $Y», за месяц по задачам и по аккаунтам; поля «Лимит в день, $»
   и «Лимит в месяц, $» (пусто — без лимита).
6. **Данные** — «Экспорт» (галочка «включить ключ OpenRouter»), «Импорт» (выбор файла + «Заменить» /
   «Объединить»), «Очистить всё».
7. **Журнал** — последние записи (время, уровень, область, текст), «Скопировать всё», «Очистить журнал».

## 9. Тестирование

Vitest, тесты в `tests/`, повторяют структуру `src/`.

- `ai`: разбор SSE (дельты, комментарии, `[DONE]`, обрыв); таблица переключения моделей (каждая строка);
  перевод ошибок; `generateJson` — оба режима, снятие обёрток, повтор при неверном формате,
  `bad_output`; рассуждение передаётся только поддерживающим моделям; таймаут и отмена;
  каталог — разбор ответа `/models`, кэш 24 ч, `force`; лимит расходов блокирует запрос, но не проверку
  ключа; каждый ответ с `usage` записан в расходы с активным аккаунтом. `fetch` подменяется.
- `storage`: значения по умолчанию, починка неверных полей, миграция; журнал — лимит 500;
  аккаунты — «Основной» при первом запуске, правила имени и @username, удаление с каскадом (кроме
  `spend`), запрет удалить последний, восстановление активного; расходы — границы суток и месяца,
  расчёт стоимости по каталогу, проверка лимитов; экспорт/импорт на `fake-indexeddb` — «заменить»,
  «объединить», отказ на более новой версии, откат при ошибке, ключ в файле/без ключа, аккаунты после
  импорта.
- `threads`: `parsePageUrl` — все строки таблицы раздела 5 для обоих хостов.
- `messaging`: типизированная обёртка на подменённом `chrome.runtime`/`chrome.tabs`, ошибка
  `no_content_script`.
- `ui`: экран настроек — сохранение полей, ограничения запасных моделей (не больше 2, без основной),
  блокировка «Рассуждения».

Ручная приёмка — критерии из раздела 1.

## 10. Решения и причины

| Решение | Причина |
|---------|---------|
| Задачи и вызовы ИИ в панели, а не в фоновом воркере | Воркер MV3 засыпает; панель живёт, пока открыта |
| Прямые вызовы OpenRouter с ключом владельца | Инструмент личный; нет посредника, который видит ключ |
| Каталог моделей с OpenRouter, а не зашитый список | Модели и цены меняются; зашитый список устаревает |
| Dexie для данных, `chrome.storage` для настроек | Тысячи постов с индексами в будущих частях; настройки маленькие и нужны синхронно-реактивно |
| Свой тонкий слой сообщений | Контракт в одном файле, легко тестировать, без лишней зависимости |
| Без автопубликации (общее правило) | Массовые автоматические действия с маскировкой нарушают правила Threads и рискуют аккаунтом |
| Аккаунты в ядре, а не позже | Владелец ведёт несколько тематических аккаунтов; без разделения данных голос одного аккаунта протекает в генерации другого, а добавить `accountId` задним числом — переделка всех таблиц |
| Учёт расходов в ядре | Свой ключ: программы будущих частей тратят деньги незаметно; лимит нужен до того, как появятся длинные цепочки вызовов |
| Расходы удалённого аккаунта сохраняются | Учёт денег не должен обнуляться от уборки аккаунтов |
